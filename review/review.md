### R1 — исправить чтение CSV-полей в кавычках

Приоритет: P2, функциональная ошибка.
Место: [CsvTable.java, строки 21–35](https://github.com/thaperfectcell/bakery-shift-planner/blob/9ddd0c27706524c50a0fdc0e3901e1086eac7eb5/src/java/src/main/java/ru/mirea/bakery/io/CsvTable.java#L21-L35).

Метод read() делит каждую физическую строку через split(";"), не учитывая кавычки.
При этом write() сам заключает такие поля в кавычки, поэтому записанный им файл
не всегда можно прочитать обратно. Минимальный пример:

```csv
name;unit
"Хлеб; свежий";шт
```

Ожидается name = `Хлеб; свежий`, unit = `шт`. Фактически Java возвращает
name = `"Хлеб`, unit = ` свежий"`. Python csv.DictReader читает этот файл правильно.
При загрузке справочников это может повредить названия и сместить значения столбцов.

Предложение: использовать CSV-парсер с поддержкой разделителей внутри кавычек,
удвоенных кавычек и переносов строк в полях. Добавить проверки чтения после записи
и сравнения с Python для этих случаев.

### R2 — не терять партии в промежутках между сменами

Приоритет: P2, функциональная ошибка.
Место: [BakeryFloor.java, строки 90–101](https://github.com/thaperfectcell/bakery-shift-planner/blob/9ddd0c27706524c50a0fdc0e3901e1086eac7eb5/src/java/src/main/java/ru/mirea/bakery/planning/BakeryFloor.java#L90-L101)
и [строки 109–122](https://github.com/thaperfectcell/bakery-shift-planner/blob/9ddd0c27706524c50a0fdc0e3901e1086eac7eb5/src/java/src/main/java/ru/mirea/bakery/planning/BakeryFloor.java#L109-L122).

Планировщик проверяет общий конец горизонта, но не проверяет, что найденному
времени начала соответствует смена. Если findShift(start) возвращает null,
партия всё равно попадает в scheduled. Затем ShiftTask.formFor() не включает
её ни в одно сменное задание; экспорт партий через задания также её пропускает.

Воспроизведение: одна печь без переналадки, смены 09:00–10:00 и 12:00–13:00
05.11.2026, одна партия с выпечкой 30 минут и сроком 17:30. При стандартном
maxLead = 7 часов начало сдвигается на 10:30. Получено: scheduled = 1,
unscheduled = 0, shift = null, сменных заданий = 0. Партию можно было поставить
на 12:00–12:30, но она исчезает из заданий.

Предложение: выбирать допустимое окно смены до назначения партии и при необходимости
переходить к следующей смене. Если окна нет — явно относить партию к unscheduled.
Если допустимы только непрерывные смены, это ограничение нужно проверять при вводе.
Добавить тест с перерывом: каждая запланированная партия должна принадлежать ровно
одному заданию, остальные — находиться в списке незапланированных.

### R3 — проверять содержимое выходных CSV в сравнительном тесте

Приоритет: P3, рекомендация по полноте тестирования.
Место: [SameResultAsPythonTest.java, строки 18–34](https://github.com/thaperfectcell/bakery-shift-planner/blob/9ddd0c27706524c50a0fdc0e3901e1086eac7eb5/src/java/src/test/java/ru/mirea/bakery/app/SameResultAsPythonTest.java#L18-L34).

Тест сравнивает консоль с сохранённым эталоном и проверяет только число созданных
файлов. Ошибка в строках, столбцах или количествах внутри CSV может остаться незамеченной.
Предложение: добавить эталонные CSV процедурной версии и сравнивать содержимое всех
шести файлов. В отдельной интеграционной проверке можно запускать обе версии на
одинаковых данных. Независимое сравнение при данной рецензии на демонстрационном
наборе прошло успешно; рекомендация касается будущих регрессий.
